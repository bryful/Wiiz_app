# Android版の開発と保存先

Android Studioでリポジトリ直下の `android/` を開きます。
SDK Platform 35、NDK 30.0.16248370、CMake 4.1.2、JDK 21を使用します。
JDK 21のインストール先を指定してください。
Gradle JDKへJDK 21の場所を指定し、Gradle Syncを実行します。

```powershell
$env:JAVA_HOME='C:/path/to/jdk-21'
cd android
./gradlew.bat :app:assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`。
arm64-v8a、minSdk 23、compile/target SDK 35。

## 配布用APK

`android/`で`./gradlew.bat :app:assembleRelease`を実行します。
Wiizと同階層の`Wiiz_signing/signing/`に`release.properties`と`wiiz-release.jks`がある場合、
配布専用鍵で署名した`android/app/build/outputs/apk/release/app-release.apk`を生成します。
署名ファイルがない環境では未署名APKになるため、そのまま配布しないでください。
署名鍵とパスワード設定はGit管理対象外です。更新版にも同じ鍵が必要なので、
`Wiiz_signing/`を安全な場所へバックアップし、配布物には含めないでください。
`release.properties`と鍵を含むZIPもリポジトリへ追加しないでください。
開発版とは署名が異なるため上書きできません。既存の開発版を使う端末では、
共有フォルダーの保存データを保全したうえで開発版を削除し、リリース版を導入します。
初回起動時には同じ保存フォルダーを選び直してください。
バージョンは0.1.3（versionCode 4）、Android 6.0以降のarm64-v8a端末用です。
ROMは含みません。既存のライセンス表示はAPK内assets/licensesに同梱します。
Wiz1パッチ由来の差分については[権利条件の未確認事項](wiz1-bugfix.md)が残っています。

## ユーザーがアクセスできる保存先

初回起動でAndroid標準のフォルダー選択を開きます。
内部共有ストレージのDocumentsを選んで「このフォルダを使用」を許可してください。
既にDocuments/Wiizを作成している場合は、Wiizを直接選んでも構いません。
Documentsを選んだ場合はその中にWiizを作成し、以下を使用します。

```text
Documents/Wiiz/
  Rom/                  ROMの原本（ユーザーが取り込んだもの）
  Save/                 ROM名.sav（または選択したJSON形式）
    backups/            通常保存処理に伴うバックアップ
  state/
    ROM名.stot1.state   Save 1 / Load 1
    ROM名.stot2.state … ROM名.stot5.state
```

新しい名前のステートがない場合は、共有フォルダー内の従来の `state/<ROMのSHA256>/slot1.json` などを読み込みます。
SAV・ステート・バックアップ・書込用一時ファイルは、指定したフォルダーへ直接読み書きします。
内部領域へSAVやステートを複製・同期する方式や、エクスポート／インポート機能はありません。
フォルダー未選択・アクセス権喪失・書込失敗時にはエラーにし、内部保存へフォールバックしません。
既存の内部SAV・ステートは移行・修復・削除しません。
アプリの設定と、エミュレーターへ渡すROMの読取用キャッシュだけは内部領域を使用します。

「ファイル」→「ROMを取り込む」で.nesを選ぶと、Romへ保存して既存コアで起動します。
同名で内容の異なるROMの上書きは拒否します。新規保存名は元ROMの安全なファイル名です。
次回起動はRomの一覧を読み直します。フォルダー変更はゲームを終了してアプリを開き直してから
「ファイル」→「保存フォルダーを指定」で行います。古いデータは移行しません。

通常SAVは8KiBのバッテリーRAMです。2秒ごと、ROM切替・終了時、中断直前に保存します。
原作がまだSRAMへ反映していない処理途中のCPU RAMまで保存するものではありません。
Save 1/Load 1は枠1固定で、ステートには音声コアと探索情報も含みます。
ステートはbinjnes/Wiiz固有のABI依存形式であり、他エミュレーターとの互換性は保証しません。

## 共有保存による周期的な停止への対処

2026-10-21: SAFのフォルダー検索・作成・書込・renameをエミュレーションスレッドで
同期実行していたため、オートセーブ中に映像・音声・入力が同時停止する経路がありました。
書込を専用の単一ワーカーへ分離。ゲーム側は不変のbyte配列スナップショットをメモリキューへ渡し、
同じファイルの待機中スナップショットは最新のものへまとめます。保存先は指定共有フォルダーだけです。
書込エラーはToastとゲームのstatusへ通知し、失敗したスナップショットはメモリ上に保持します。
リセット・ROM切替・明示的ステート保存・中断・終了時には書込完了を待ちます。
ゲーム中の定期保存では待ちません。SAV時の不要なJSON生成を省略し、
探索情報は初回または変更時だけ書き出します。

SaveQueueTest: 遅い保存先でもenqueueが返ること、不変コピー、最新への集約、順序保証、
flush完了待機、書込失敗通知と後続書込の拒否をJDK21で検証し成功。
修正APK assembleDebug成功。Pixelで周期停止が解消したかは実機確認待ちです。
