# パーティーのアイテム編集

FC版Wizardry I・II・IIIの確認済み配置で利用できます。
**1人以上の有効なパーティーがいれば、戦闘中を除くすべてのシーンで利用できます。**
町・酒場・宿屋・商店・寺院・町外れ・キャンプ・迷宮など、場所による制限はありません。
訓練場への入場で原作がパーティーを解散した場合は、パーティーなしとして扱います。
パーティーがない場合と戦闘中は開けません。処理途中の所持品転送は完了してから開きます。

Windowsは `I`、または `Q` → `Party items`。
Androidは「アイテム」ボタン、または「設定」→ `Party items`。
編集中はゲームを停止し、変更は操作ごとに通常セーブへ保存します。
ROM・所持品の新規生成・識別・呪い解除は行いません。

## 操作

左右に2人の名前と所持品を表示します。1人の場合、右側は相手なしです。
名前とアイテム名は使用中ROMの日本語CHRフォントから描画します。
選択中の品は画面下部にも名前を表示します。

| 操作 | 動作 |
|---|---|
| 左右 | 操作する側を選択 |
| 上下 | 所持品8枠と一括操作を選択 |
| Select / Start、WindowsのA / S | 操作側の人物を前後に変更 |
| 名前の左右をタップ・クリック | 人物を変更 |
| A、WindowsのX / Enter | サブメニューを開く・実行 |
| B、WindowsのZ / Backspace | 取消、通常画面からゲームへ戻る |
| WindowsのI、Androidの「アイテム」 | 通常の編集画面を閉じる |

サブメニューは装備・解除、相手へ移動、削除、上へ移動、下へ移動。
装備中には `*`、呪われた未装備品には `!` を表示します。
装備・呪い状態の品は移動・削除できません。未識別品は装備できません。
職業制限を確認し、同種の装備は置換します。呪われた装備の解除・置換は禁止します。
原作同様、属性不一致や呪い付きの品を装備すると呪い状態になります。
削除確認は「いいえ」が初期値です。

- `COLLECT UNIDENTIFIED`：他の全員から操作側へ、空き枠分だけ未識別品を集める。
- `SEND UNEQUIPPED`：操作側から反対側へ、空き枠分だけ未装備品を移動する。

一括操作も装備中・呪いのある品を除外し、全フラグを保持します。

## 原作処理と既存実装の再利用

- GBWiz `src/item_menu.h` の2人表示、操作順、削除確認、一括処理をFC版へ移植。
  MIT、Copyright (c) 2026 bryful。ローカルの参照ソース・LICENSE・SHA256を
  `third_party/gbwiz-items/` に保持しています。Gambatteは組み込みません。
- 既存のbinjnes（MIT）のMapper 1 / 4、ステート保存・復元を利用。
  実行中のステートを独立した同じコアへ読み込み、**ユーザーのROMの原作ルーチン**で能力を再計算します。
  新しいエミュレーターや近似的な能力計算は追加しません。
- 人物・所持品配置とセーブの複製・チェックサムは既存WizEdit移植部分（MIT）を再利用。
  変更前バックアップは既存の `backups/<ROM名>/` へ保存します。

| 作品 | 人物配置（SRAM内） | 状態 / 番号 / 個数 | 原作の能力再計算 |
|---|---|---|---|
| I | $0000、256バイト×20 | +$4C / +$54 / +$5C | PRG 16KiB bank 6、$AE6F |
| II | $0400、96バイト×20 | +$43 / +$4B / +$53 | 固定bank $D05A、PRG 16KiB bank 6、$BDED |
| III | 同上 | 同上 | 固定bank $D05C、PRG 16KiB bank 6、$9E3D |

状態はbit5が未識別、bit7が装備、bit6が呪い。他のビットも保持します。
開く際に原作の命令列、有効なパーティーと戦闘状態を確認します。
FC-Iは固定bankの戦闘ディスパッチャーと実際のJSR戻り先、II・IIIは原作の戦闘フラグ$90を参照します。
場所や呼出元による許可リスト、迷宮入力待ちの条件は使用しません。
適用前に人物参照と所持品が一致することを再確認し、複数人をまとめて更新します。
能力再計算に失敗した場合は保存しません。
再計算コアのCPU・PPU・Mapper・画面を実行中コアへ取り込まず、
必要な能力配列と人物のAC・所持効果だけを反映します。
町の作業領域を壊さないよう、元の人物レコードとHP・レベル・状態が一致する読み込み済みの能力配列だけを更新します。
元のメニューの所持品キャッシュも、人物参照・個数・全所持品が一致する場合に同期します。
HP・MP・呪文・経験値・他の人物データを保持します。
ステート読込に成功した場合は編集画面を終了します。

## 検証

`--items-check <ROM> <専用検証フォルダー>` はローカルROMで探索状態を用意し、
装備・解除、原作の武器ダメージ反映、並べ替え、削除、受け渡し、一括収集・移動、
識別フラグ、呪いの削除禁止、削除確認の初期値、古い所持品の拒否、
他フィールドの保持、通常セーブ再読込、原作を再開した後の保持を確認します。
検証用ROM・セーブ・ステート・画面はGitへ追加しません。

未確認：Android実機での表示・タッチ操作、全アイテム・全職業・全属性の組合せ、
全パーティー構成、任意の改造ROM。戦闘中は仕様として対象外です。

2026-11-21確認：通常版・パラメーター変更版の6本で上記の編集検証とSDLでの開閉・サブメニュー・ステート読込時の終了が成功。Windows x64 Release、Android arm64-v8a Releaseのビルド成功。Androidの15操作ボタンは縦横・小画面・タブレットの8条件で重なりなし。Android実機は未確認。

シーン制限撤廃の検証は `--items-scenes-check <ROM> <専用検証フォルダー>`。原作の酒場操作でパーティーを作り、町と各施設・キャンプでの編集、元の画面の維持、再開後の所持品保持を確認します。別の専用セッションで原作のエンカウント入口を実行し、戦闘中と戦闘ステート再読込後の拒否を確認します。ROMや戦闘フラグを書き換える検証ではありません。

同日の追加確認：通常版・パラメーター変更版の6本で14場面（迷宮、キャンプと人物画面、酒場と人物選択、城、宿屋と人物選択、商店と人物選択・所持品一覧、寺院、町外れ）の編集・再開が成功。原作の訓練場での解散後はパーティーなしとして拒否。原作エンカウント入口の実行中と戦闘ステート復帰後の拒否も確認しました。

アイテム移動時の再計算でコアが未対応命令を検出した場合は、アプリを終了せず編集画面にエラーを表示します。失敗した変更は保存しません。FC版Iでは、再計算用コアのMMC1バンク切替を初期化します。
