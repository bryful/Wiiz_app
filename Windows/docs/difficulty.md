# 難易度調整（最初の実装）

対象は配置を確認したFCⅠ・Ⅱ・Ⅲとパラメータ変更版。

- Q → Difficulty / bonuses → Characterで登録名簿の1〜20番を選択（左右で変更）。空欄は拒否する。
- Amountは1,000 / 10,000 / 100,000 / 1,000,000。Add experience / Add GoldをXで実行するたび、その量を対象1人へ加算する。12桁上限で止め、桁あふれさせない。
- Learn all spellsは対象1人の両系統・全レベルの習得フラグを設定する。職業、レベル、現在MP・最大MPは変更しない。使用可能条件は原作に従う。
- 名簿操作は街や迷宮の移動待ちで使用する（戦闘中・施設処理の途中は未検証）。経験値による成長・レベルアップも原作の処理に従う。
- Mで探索済み地図を直接表示、X / Zで閉じる。原作のデュマピックを実行せず、MPを消費せず、閉じる入力も原作へ送らない。表示中はゲームを停止する。マロールやデュマピックを実際に唱えた場合の既存機能も利用できる。
- 原作画面の上に階・東座標・北座標・方角（N/E/S/W）を表示する。地図を開けない座標では表示しない。

変更は実行中のSRAMに反映し、通常の自動保存に従う。ステートを読み込むと名簿も保存当時へ戻る。
灰・喪失防止、暗闇そのものの無効化、宝箱の罠無効、所持アイテムの識別はまだ実装していない。

## 再利用と出典

既存binjnes（MIT）のSRAM APIとRAM読取、SDL3（zlib）の既存メニューとマップ表示を使用。新規依存・エミュレーター実装はない。
名簿のGold/経験値・呪文習得の配置はthird_party/wiz-save/WizData.cs（bryful/Wiz、MIT、Copyright (c) 2019 bryful）のCharGoldFromIndex、CharExpFromIndex、CharSpellFromIndexを根拠にする。
Ⅰは50bitの習得配置、Ⅱ・Ⅲは14バイト。Ⅱ・Ⅲの各レベルの有効ビット数はtools/item_spell_data.pyと同じROM境界表を使用し、対象外ビットを保持する。
既存repairBatteryでチェックサム・複製を更新する。既存third_partyのLICENSE・PROVENANCEを保持する。

検証用: wiiz.exe --difficulty-check ROM 一時出力フォルダ。
既存の実ROM操作によるマップ準備を経て、地図の非消費、状態保存復元、経験値/Gold加算、上限、全呪文フラグ、MP維持、セーブ再読込、原作の登録受理を確認する。
全戦闘終了・施設・職業ごとの使用可否は未検証。

## MP固定と常時効果

Q → Difficulty / bonusesの末尾に次の4項目を追加。Xまたは左右で個別にON/OFFにする。初期値はすべてOFF。選択した設定はアプリを閉じても保持し、Ⅰ・Ⅱ・Ⅲで共通に使用する。

- MP fixed at 9 (all characters): 登録済み全キャラの魔術師・僧侶両系統、全7レベルの現在MPと最大MPを9に固定する。未習得呪文の習得、沈黙や使用場所の制限解除は行わない。OFFにしても、変更したMPを以前の値には戻さない。
- Always LOMILWA: 照明の効果フラグを維持する。暗闇での解除書き込みも抑えるが、暗闇地形そのものを通常地形へ変える機能とは別。
- Always LATUMAPIC: 敵の識別効果を維持する。所持品の鑑定ではない。
- Always MAPORFIC: 原作の保護効果フラグを維持する。

常時効果をOFFにすると固定を解除する。残った効果は原作の解除処理に従う。
MPの変更は通常セーブにも残る。通常セーブ・リセット前に既存のチェックサム補完を行う。起動時の登録検査中は固定を開始せず、原作の起動完了を待つ。
ステートを読み込んでも現在のON/OFF設定を維持する。古い版のステートは次の探索待ちか設定操作で固定を開始する。

### 接続位置・出典

提供されたファミコンチート集Wikiの[Ⅰ](https://wikiwiki.jp/nnnes1/ウィザードリィ)、[Ⅱ](https://wikiwiki.jp/nnnes1/ウィザードリィ２)、[Ⅲ](https://wikiwiki.jp/nnnes1/ウィザードリィ３)を調査の手掛かりにし、MPは既存WizData.csの配置と照合した。コードの一括取り込みではなく、ROM固有のアドレスと値を接続層に記録する。

|---|---|---|---|---|
|Ⅰ|$29～$44、各バイト9|$027F=FF|$0280=FF|$0281=FE|
|Ⅱ|$27～$34、各バイト99|$77EF=FF|$77F1=FF|$77F0=02|

## 作成時の最大ボーナス

Q → Difficulty / bonuses → Max creation bonus (species cap)をONにする。初期値OFF、設定はアプリ終了後も保持する。新しく作成するキャラクターに適用され、既存キャラクターや割り振り途中のポイントは補充しない。

Ⅰ・Ⅱは人間62、エルフ60、ドワーフ60、ノーム59、ホビット58点。Ⅲは全種族60点。Ⅰでは原作の自然生成上限29点を超え、全能力を18まで上げられる。Ⅲの上限は種族の基礎能力＋10。64点固定では余りが出るため、配分可能な最大点数を使用する。

既存binjnesのRAM書込監視で、原作のボーナス生成後に一度だけ残りポイントを設定する。点数の増減・返却、職業候補、登録・保存は原作が処理する。原作のCPU/MapperやROM自体の変更は追加しない。根拠は[creation-bonus.md](creation-bonus.md)。

検証用: python tests/check_native_creation.py output/native-build/windows-vs/Release/wiiz.exe
