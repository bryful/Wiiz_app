# 全体高速化と等速音楽・入力

2026-10-20。対象はコード配置と音声処理を照合したWizardry FC I/II/IIIと、そのパラメータ変更版。
対応コードを確認できない改訂では1倍で動かし、未検証のRAM接続を適用しない。

## 実装

- 画面更新約60.1Hzごとにゲーム用binjnesを1/2/4/8フレーム実行し、最後の完成フレームを表示する。
  CPU/PPUの待ちを飛ばさず、元のNMI、転送、OAM消去を全て実行する。ROMの変更はない。
- 音声専用のもう一つのbinjnesを1フレームだけ実行する。原作ROMの初期化と音楽ドライバー、既存APUを再利用する。
  ゲーム側の音声要求RAM $0600（BGM）、$0601/$0602（SE）への書込を渡す。
  音楽専用側のタイトル画面由来の要求は遮断し、PRG16KiB bank 2の音声ドライバー自身の停止・完了書込は通す。
  音声の間引き、再生周波数変更、独自の音源実装は使わない。
- 方向キーは物理的な押下状態を保持し、原作のリピートカウンター $1D–$20を接続層から管理する。
  最初の長押し待ちは200ms、以後100ms間隔。要求は原作の入力ポーリングが消費するまで保持する。
  A/B/Select/Startは原作の押下エッジ処理を使い、ホストのキーリピートイベントは無視する。
- Q → Display / speedのSpeed項目をXで1→2→4→8→1と変更する。初期値4倍、speed.txtへ保存する。
  撤回済みのfast-drawing.txtは引き続き無視する。
- 1倍で起動した場合は元の音声経路。高速化開始後は1倍へ戻しても音声専用側を続ける。
  高速化への切替時には現在のBGMを先頭から再開する。Escapeはゲーム用コアのRAMを保ったリセット要求を使い、音声専用側を破棄する。
  保存するSRAMはゲーム用コアだけで、音声専用側は保存しない。

## 既存実装と権利表示

binjnesの既存CPU/PPU/APU/MMC1、既存のweb/audio/driver.jsとtools/probe_se.mjsの
ROM音声ドライバー呼び出し・要求フィルターを再利用した。新しいエミュレーターコア・音源は作っていない。
binjnesはMIT、パレットはMIT-0。著作権表示と各LICENSEを保持し、配布フォルダにも同梱する。
外部ランタイム依存は追加していない。ROM・BGMのデータを実行ファイルやパッケージに含めない。

emulator.c/hに、任意のRAM書込監視・フィルターコールバックを追加した。
NULL時は元の動作。CPU/PPU/APU/Mapperのアルゴリズムとシリアライズ対象Sのレイアウトは変えていない。
上流リビジョン、元と採用後のハッシュ、差分はthird_party/binjnes/PROVENANCE.jsonとwiiz-ram-observer.patchに記録。

## 検証と限界

`wiiz --turbo-check .nes/wiz1.nes`で以下を検証する。

- 2/4/8倍で180ホスト更新：ゲームは360/720/1440フレーム進み、各更新の映像が独立した参照コアと全ピクセル一致。
- 各速度の音声は143872サンプルで一致し、有限値・非無音。ゲームの速度に音声生成量は比例しない。
- 城で下キーを2秒長押し：原作のカウンターが消費したリピートは各速度18回。
- 音声ドライバーのBGM13曲と$0602系SE13種類、停止要求、リセット後の再開を実行。

通常経路は既存の3作品起動・SRAM往復・リセット検査、全フレームの映像/音声比較とSDL入力リプレイで回帰確認する。
SDLの実描画・音声経路では4倍速のタイトル→城→編成→迷宮リプレイも実行する。

短いSEが同じホスト更新中に連続発生すると、要求RAMごとに最後の要求を優先する。
高速化された演出よりSEが長く続く場合があり、全SEの重なり方・実機との聴感一致は未検証。
以前報告された宝箱直後の場面そのものはまだ再現できておらず、この場面の残像解消を断定しない。
全戦闘・宝箱パターン、Android実機は未対応または未検証。

## Ⅱ・Ⅲへの適用

採用済みbinjnes（MIT）のCPU/PPU/APU/MMC3実装を継続利用する。
調査した既存コア候補との比較・採用理由はnative-core.md、出典・固定リビジョンは
third_party/binjnes/PROVENANCE.jsonに保持する。上流コアへの追加改変や依存追加はない。

- 音声ドライバーはPRG8KiB bank 5。$0600（BGM）、$0601/$0602（SE）を転送し、
  $0603の継続する副音楽要求もゲーム側の状態に合わせる。ドライバー自身の完了書込は通す。
- $0603は継続状態として読むため、追加のコマンドキューやステートのバイナリ形式変更は不要。
- 方向キーカウンターは上$13、下$12、左$11、右$10。
  解放$0E、繰り返し要求$FF、保持中$F4を原作へ渡す。A/Bの押下判定は原作を使う。
- ⅡはBGM4種類、SE要求13種類＋副音楽13種類、ⅢはBGM4種類、SE要求13種類＋副音楽12種類を実行する。
  Ⅰの13曲/13SEという番号範囲をⅡ・Ⅲへそのまま適用しない。

```powershell
python tests/check_native_turbo.py output/native-build/windows-vs/Release/wiiz.exe .nes/WIZ2.nes
python tests/check_native_turbo.py output/native-build/windows-vs/Release/wiiz.exe .nes/WIZ3.nes
```

各作品の2/4/8倍で参照コアとの画素一致、180更新あたり143872音声サンプル、
方向キー2秒長押しのリピート18回を検査する。音楽コアを含む4倍速ステート復帰も検査する。
