# デュマピック・マロールの探索済みマップ

対象はコード配置を確認したFCⅠ・Ⅱ・Ⅲと、そのパラメータ変更版。キャンプで原作の呪文を選び、発動した場面だけアプリのマップへ切り替える。
各作品の原作の消費・転移判定を保つ。
左下原点の20×20マップ・右側の階層一覧・現在位置の矢印を表示する。表示はFC版の配色・文字・枠の雰囲気に合わせる。
SNES版の画像素材やROMデータを取り込む方式ではない。

## 操作

- デュマピック：現在の階の探索済みマップと赤い現在位置・方角を表示。XまたはZで閉じる。
- マロール：方向キーで黄色の行き先カーソルを移動。A（Select）で上の階、S（Start）で下の階へ切替。
  Xで原作のマロールを実行、Zでキャンセル。方向キーの長押しは200ms待ち・100ms間隔で、ゲーム倍率から独立する。
- SURFACEは地上への帰還を選ぶ項目。原作の地上座標(0,0)を指定する。
- グレーは未探索、黒は探索済み。未探索の壁・扉・イベントは描かない。
  既に歩いたマスの四辺を表示し、隠し扉の種別は明かさず壁として描く。暗闇のマスの形状も表示しない。
- 未探索の行き先も選択できる。禁止階・範囲・石への転移などの判定は原作のまま。

探索記録は**この版で歩いた場所から**蓄積する。以前のセーブから、過去に歩いた場所を推測して埋めない。
通常セーブJSONの `exploration` にⅠは4,000マス、Ⅱ・Ⅲは各2,400マスの0/1配列で保存する。
ステートには探索記録、開いている呪文マップ、カーソルと原作への再開入力も保存する。
旧ステートの読込にも対応するが、記録のない古いステートから過去の探索は復元できない。

## 既存機能の再利用

- マップ抽出は既存のapp/dungeon.cpp、tools/dungeon_data.pyの照合済みROM配置を使用する。
  読み出しは配置を確認したⅠの10階、Ⅱ・Ⅲの各6階。8,800マスの既存照合を維持する。
- CPU/PPU/APU/Mapperは既存binjnes（MIT）。追加のCPUコア・音源・転移ルールは作らない。
  音声分離で追加済みの任意RAM書込コールバックを、ゲーム側の状態の読取にも再利用する。
  EmulatorのSや上流のCPU実行・描画・Mapperの処理を追加改変しない。
- 表示と入力は既存SDL3（zlib）、保存は既存nlohmann/json（MIT）を使用する。新規依存はない。
  ライセンス・出典は既存のthird_party/とインストール先licenses/に保持する。

Ⅰの原作コードで確認した接続位置：

| 内容 | 位置 |
|---|---|
| 現在位置・方角 | CPU RAM $3B=東、$3C=北、$3D=階、$3E下位2bit=方角 |
| 探索入力待ち | 固定bankの$D2D6で$0279を書き、PC=$D2D9。現在マスだけ記録 |
| デュマピック | PRG16KiB bank 2、$A66Bで$0Eへ階を書き、PC=$A66D |
| キャンプのマロール | bank 6、$B486で$2Bを初期化、PC=$B488 |
| マロールの入力先 | $021E=東差分、$021F=北差分、$0220=階差分（符号付き） |
| 原作の決定後 | $B4BE以降。消費処理$BF73を通し、$B4F3以降で原作が座標と移動可否を判定 |

上記の書込は読み取りだけで検出し、元の命令を止めたりROMを書き換えたりしない。
表示中はゲーム側を止め、等速音声用コアを動かす。閉じるときに解放→決定/取消→解放を原作へ送り、
選択結果を元の入力待ちへ戻す。MPや座標をアプリが直接減算・転移させる方式ではない。
戦闘中のランダム転移は変更しない。

## 検証

```powershell
python tests/check_native_spell_map.py output/native-build/windows-vs/Release/wiiz.exe
python tests/check_native_persistence.py output/native-build/windows-vs/Release/wiiz.exe
python tests/check_native_drawing.py output/native-build/windows-vs/Release/wiiz.exe
```

専用の一時フォルダで、対象ROMを起動し、テスト用の魔術師を準備して酒場・迷宮・キャンプ・呪文選択を実際に操作する。
PCを呪文の途中へ飛ばすテストではない。デュマピックの実発動とMP消費、マロールの実発動・キャンセル時の非消費、
地上帰還、B1東0北1への転移を確認する。1/4/8倍速で同じ転移結果・1回分のMP消費を照合する。
探索記録の通常JSONへの保存と再読込、呪文マップを開いた状態でのステート復帰も確認する。
SDLキーイベントで閉じる操作、移動先・階層選択・決定・取消を通し、未探索セルがグレーのままであることも画像検査する。
通常経路は起動900・迷宮4,300・戦闘復帰11,000フレームの全画素と音声を参照コアと照合する。
ユーザーの既存セーブとROMファイルは検証で変更しない。

未検証：全階・全禁止条件・全転移失敗パターン、照明中の暗闇の記録、イベントによる壁形状の変化、Android。
表示する壁はROMの初期地形を参照し、秘密の扉の発見状態などは追加推測しない。

## Ⅱ・Ⅲの接続と検証

PRG8KiB bank番号を既存binjnesと同じマスクで正規化する。
Ⅱはbank番号の上位ビットを設定するため、生のMapperレジスターを比較しない。
可変bankは物理bankとbank内オフセットで照合する。

| 内容 | Ⅱ | Ⅲ |
|---|---|---|
| 座標・方角 | $EA=東、$EB=北、$EC=階、$E9下位2bit=方角 | 同左 |
| 探索待ち（bank 13、$BF書込後のbank内PC） | $00CA | $05DC |
| デュマピック（bank 12、$B1書込後） | $104D | $1035 |
| マロール初期化（bank 7、$C2書込後） | $0EB2 | $0D82 |
| マロール入力 | $C0=東差分、$C1=北差分、$C2=階差分 | $C2だけ階差分の符号を反転 |

原作メニューから詠唱し、各呪文のMPが1回だけ減ること、取消時のMP返却、
1/4/8倍でB1東0北1への転移、地上帰還を確認する。原作の呪文レベル選択には左キーを使う。

```powershell
python tests/check_native_spell_map.py output/native-build/windows-vs/Release/wiiz.exe .nes/WIZ2.nes
python tests/check_native_spell_map.py output/native-build/windows-vs/Release/wiiz.exe .nes/WIZ3.nes
```

同じ検査をwiz2p.nes・wiz3p.nesにも適用する。SDL入力による表示・閉じる・移動先決定・取消、
探索記録のJSON保存、マップ表示中のステート復帰も検証する。
全禁止条件・最終階・石への転移などの網羅的検証は未実施。原作のルールを置換しない。

## FC版に寄せた表示調整（2026-10-21）

Android・Windows共通でマップを拡大し、壁と枠を4論理ピクセル、扉の中央を6論理ピクセルへ変更。
原作のCHR文字を、既存のキャラクター名と同じ確認済みフォントバンク・ビット面の接続で再利用します。
未探索はグレー（96,96,96）、探索済みは黒、壁と枠は白。
現在位置と方角は赤、マロールの移動先は黄色を維持します。
独自のマップ表示を原作のデュマピックそのものと同一とは扱いません。
隠し扉・暗闇・未探索の非表示条件、転移判定、MP消費は変更しません。
3作品の実呪文発動、1/4/8倍速の転移、キャンセル、未探索非開示の回帰テスト成功。
