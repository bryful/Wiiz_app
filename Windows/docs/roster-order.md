# キャラクターのslot順の入れ替え

## 操作

名簿に登録されている20枠の順序を変更する。パーティー内の前列・後列を並べ替える機能とは別。

1. 起動直後のタイトル、または原作の保存を終えてEscapeでリセットした後のタイトルでQを開く。原作へ進むボタンを押す前に操作する。
2. Roster order (title only)を選ぶ。
3. 20人分の一覧で上下キーを使い、移動したいキャラクターへカーソルを合わせる。原作フォントの名前とレベル、空き枠も表示する。
4. XまたはReturnで選択する。カーソルの「*」が移動中の目印。
5. 上下キーで移動先へ動かす。間にいるキャラクターは1枠ずつずれる。先頭・末尾では止まる。
6. XまたはReturnでもう一度決定すると保存する。ZまたはBackspaceは選択前の並びに戻す。Qで閉じた場合も未確定の移動は破棄する。

確定した並びは通常セーブに保存し、原作をタイトルへ再起動する。メニューは開いたままなので続けて移動できる。ゲームを開始した後・ゲーム中のステートを読み込んだ後は、先にタイトルへリセットしてから行う。

タイトル限定なのは、原作が保持する一時的なキャラクター参照を再起動で作り直すため。戦闘や施設処理中のレコードを直接交換しない。Escapeを使う前は原作のセーブが済んだ状態にする。保存範囲は原作のSRAM更新タイミングに従う。

交換前の通常セーブはsaves/backups/<ROM名>/の日時付きbefore-rosterファイルに自動退避する。通常セーブがSAVならSAV、JSONならJSONを退避する。
ステートを読み込むと、名簿順もステートを保存した時点へ戻る。

## 保持するデータ

名前・職業・能力値・経験値・Gold・HP・MP・所持品・装備・状態・迷宮内の位置・未解釈フィールドを含むレコード全体を交換する。空きslotとの交換にも対応する。
チェックサムと複製領域は既存repairBatteryで再構成する。パーティーのslot参照も交換先へ付け替え、同じキャラクターがパーティーに残るようにする。

## 再利用と出典

既存third_party/wiz-save/WizData.csのSwapChar / CurrentDataUp / CurrentDataDownを根拠に、全レコードの交換をapp/save_json.cppへ移植した。
出典はbryful/Wiz、固定リビジョン020e0b5eb180595d7ce879d8305ed3792c49455d、MIT、Copyright (c) 2019 bryful。元のソース、LICENSE、PROVENANCEを保持し、配布先licenses/WizEdit.txtにも表示する。新規依存はない。
既存binjnes（MIT）のSRAM API・リセットAPIと、既存SDL3（zlib）のQメニューを使用する。CPU/PPU/APU/Mapperは追加実装・改変しない。

|作品|レコード配置（SRAM内）|パーティー参照（CPU）|
|---|---|---|
|Ⅰ|開始$0000、256バイト×20|人数$7DEF、配列$7DDC～$7DE1、値はレコードのページ$60～$73|
|Ⅱ・Ⅲ|開始$0400、96バイト×20|人数$6B81、配列$6B82～$6B87、値は0始まりのslot番号|

Ⅰの配列は原作bank 6の$89BB～$89D3の酒場加入処理、$9A24以降のキャラクター読込で確認した。Ⅱ・Ⅲは既存の$7FC0キャラクターポインター表を参照するパーティー処理と照合する。交換後は再起動し、画面の選択キャッシュ・一時ポインターを再利用しない。
Qメニューの名前は使用中ROMのCHRフォント（I: 4 KiB bank 4、II/III: bank 1）を原作文字コードで直接描画する。既存tools/extract_chr.pyと同じ2bppタイル読み取りをUIに利用し、最大8コードを2倍で表示する。slot入れ替えと経験値・Gold加算・全呪文習得の対象選択で共通利用し、名前コードは変更しない。フォント自体は同梱しない。

## 検証

```powershell
python tests/check_native_roster.py output/native-build/windows-vs/Release/wiiz.exe
```

既存の原作メニュー操作で実際の魔術師を編成し、迷宮に入った状態を用意する。ゲーム中の交換拒否と無変更を確認し、タイトルへ戻ってslot 1/2を交換する。
交換した2人の全ペイロードと他の18人の保持、迷宮パーティーの再開、同じ魔術師による原作デュマピックの実詠唱とMP消費を確認する。空slot 20への移動・逆交換・同一slotの無操作・範囲外拒否・通常セーブからの再起動・退避ファイルも検査する。
SDLキーイベントによる20人一覧のX/Return選択・決定、slot 1→20→1の挿入移動、上下端の停止、Z取消、Qで閉じて開き直した際の取消を、保存レコードと照合する。通常の交換と同じ処理を隣接slotへ順に適用し、確定時に1回だけ保存・バックアップ・再起動する。
