# パラメータ変更ROMの識別

2026-10-20。通常版に加え、wiz1p.nes / wiz2p.nes / wiz3p.nesが読めない件を調査。
直接の原因はアプリのROM識別がファイル全体のSHA-256を3個だけ許可していたこと。
ファイル名の問題ではなく、初期キャラクターやCHRを変えただけでも別ハッシュになるため一覧から除外された。

## 対象ファイルの差分

| ROM | Mapper | PRG内の変更バイト数 | CHR内の変更バイト数 | その他 |
|---|---:|---:|---:|---|
| wiz1p.nes | 1 | 320 | 5,373 | ヘッダーのミラー情報1bit変更、旧ファイル末尾の128bytesなし |
| wiz2p.nes | 4 | 275 | 0 | 予約ヘッダーバイト12〜15がゼロに変更 |
| wiz3p.nes | 4 | 280 | 0 | ヘッダー変更なし |

PRG差分は初期キャラクターのレコード領域にある。Ⅰの音楽・呪文bank、キャンプbank、固定bank、マップ領域は一致する。
3本ともiNESが宣言するPRG/CHRサイズを満たし、既存参照コアJSNES 2.1.0で720フレーム、映像の非単色・有限の音声出力を確認した。
この参照コア検査を、Windows版binjnes/SDLアプリの動作検証とは区別する。

## 識別方式の変更

- iNES形式、宣言された長さ、Mapperを確認する。ファイル名は判定に使わない。
- 固定PRG bankにある6か所の128byteコード断片の指紋でⅠ・Ⅱ・Ⅲの系統を判定する。
  少なくとも3か所が一致し、対応Mapperも一致した場合だけ採用する。複数作品に一致する曖昧な結果は拒否する。
- 初期キャラクターデータ・CHR画像・予約ヘッダー・末尾付加情報は、この系統判定に含めない。
  今回の3個の新しいファイルハッシュを単純に許可リストへ追加する方式ではない。
- 固定アドレスを使うJSONのキャラクター解釈は、固定bankとキャンプbankが既知の配置に一致する場合に使う。
  等速音楽・キーリピート分離・呪文マップは、音楽・呪文bankも一致した場合だけ有効にする。
  今回のp版3本は既知配置として判定され、3本とも拡張機能の条件も満たす。
- Wiz系統と判定できてもコード配置の一致が確認できない場合は、既存コアによる1倍実行と
  生SRAMを数値配列で保存するJSON形式 `wiiz-battery-raw` に切り替える。未検証のRAM位置やCRC補完を適用しない。
  ステート機能は同じROMに対して使用できる。
- 通常セーブのファイル名はROM名とする。SHA-256はステートの保存先、JSONのROM照合、読込中のファイル変更確認に使う。
  通常版と別名のデバッグ版にはそれぞれのROM名の通常セーブを使い、ステートは引き続きROMのSHA-256で分ける。
- 一覧とウィンドウ名に実ファイル名も表示し、同じ作品の複数ROMを選び分けられるようにする。

任意の改造ROM・海外版・別プログラム構造を無条件に受け付ける機能ではない。
判定できない新しい系統には指紋の追加調査が必要。NES 2.0の拡張ヘッダーは現段階では未対応。
コード断片の指紋はROMそのものを同梱せず、PicoSHA2（既存MITライブラリ）を再利用する。
エミュレーターコアは既存binjnes（MIT）のままで、独自のMapper/CPUを作らない。

## ソースと検証

- app/rom_identity.cpp / .hpp: C++アプリの識別処理。
- app/rom_identity_profiles.json / rom_identity_data.hpp: 基準コードの指紋。ROMバイトは含めない。
  `python tools/generate_native_rom_identity.py`でJSONからC++ヘッダーを再生成でき、`--check`で不一致を検出する。
- tools/rom_identity.py: 同じ基準データを使用する解析用識別。
- tools/rom_profiles.py: パラメータ変更版の、既知配置としての既存解析への接続。
- tests/test_rom_identity.py: 元3本・p版3本、新しいパラメータ/画像変更、コード変更時の機能制限、
  別Mapper・無関係データ・切り詰めの拒否、元とp版の全マップ一致などを検査。
- tests/check_native_edited_roms.py: ネイティブ再ビルド後に実行する、改名p版の起動・JSON・マップ・生SRAMフォールバック検査。

```powershell
python -m unittest discover -s tests -p test_rom_identity.py -v
python tests/check_native_edited_roms.py output/native-build/windows-vs/Release/wiiz.exe
```

識別のPython側9検査、既存を含むPythonテスト全34件と、既存JSNESでの3本の起動を確認済み。
Windows版を再ビルドし、改名したp版3本それぞれのネイティブ720フレーム実行、
構造化JSONセーブ、元ROMと一致するマップ抽出、3本の一覧認識を確認した。
配置が未知のWiz改訂を模したデータでも、ネイティブ実行と生SRAM JSON保存・再読込を確認した。
既存3本の起動・リセット、SDL入力、5枠ステート、JSON編集、呪文マップ、
高速化時の等速音楽とキーリピートも回帰検査済み。
新しい配布先は `output/native-settings-package/wiiz.exe`。

Ⅱ・Ⅲの音声指紋はPRG8KiB bank 5だけを照合し、隣のbank 4の初期キャラクターデータは含めない。
呪文接続に使うbank 6・7は別の16KiB指紋で確認する。コードを変えた版は系統認識と起動を維持し、拡張機能だけ無効にする。

メーカー表示スキップには起動コードの短い領域も別指紋で照合する。タイトル処理だけが異なる版では他の確認済み機能を保ち、省略だけを無効にする。
